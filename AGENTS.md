# Работа над «Хрюкерсы CDP»

Кейс №2 SibКод. Рабочая папка этого компьютера — `/data/sibcode`; на других компьютерах используйте корень клонированного репозитория. Это продукт для общей клиентской базы торгового центра. Целевой интерфейс — desktop для Linux и Windows на Tauri 2; React используется также в браузерном режиме для проверки. Backend — FastAPI/PostgreSQL с отдельными worker и dispatcher.

## Перед изменениями

- Прочитайте `README.md`, `docs/TEAM.md`, `docs/DESKTOP.md` и относящиеся к задаче модули. Актуальный контракт — `docs/api/openapi.json`; примеры для seed и регрессионных тестов — `apps/api/fixtures`.
- Работайте в своей feature-ветке. Не выполняйте force push и не переписывайте чужие изменения. Разделение задач на троих описано в `docs/TEAM.md`.
- Не добавляйте `.env`, cookie, токены, реальные контакты, БД, node_modules, target и локальные выгрузки в Git. Только `.env.example` и `.env.e2e.example` являются публичными шаблонами. Материалы отбора, устаревшие ТЗ и личные промпты храните вне Git. Перед отправкой запускайте `python3 infra/check_repository.py`.

## Инварианты продукта

- Все профили, сегменты и кампании ограничены текущим ТЦ. По актуальному требованию записи сопоставляются по нормализованному телефону ИЛИ email без общего ключа источников. Если контакты указывают на разные профили, отклоняйте строку с identity_conflict. Совпадение контакта — бизнес-правило сопоставления, а не проверка личности. Подробности: docs/IDENTITY.md.
- События идемпотентны по ключу источника; изменённое содержимое существующего события считается конфликтом.
- Новые записи всех арендаторов: только phone, email, time; создаётся interaction. Покупку, бронь и физический визит по ним не выводим. Основной поток — API по расписанию; файлы используют те же поля. Позиция API и явная гарантия полноты обновляются только после полной успешной обработки. См. docs/INTEGRATIONS.md.
- Роли marketer/admin/brand проверяются сервером. Общая база, сегменты, радар и выгрузки доступны только marketer/admin. brand привязан к одному активному арендатору своего ТЦ и использует только /brand: предпросмотр, сопоставление колонок, импорт и журнал своего источника. Управление арендаторами, подключениями, покрытием и сотрудниками — admin. Значения серверных CONNECTOR_SECRET_* в клиент не возвращаются.
- В кабинете бренда исходная таблица разбирается для предпросмотра, в хранилище импорта сохраняются только phone/email/time. Не продвигайте API cursor и не выводите полноту истории из ручного файла. См. docs/BRAND_PORTAL.md.
- Отсутствие события подтверждается только при достаточном покрытии истории. Unknown нельзя выдавать за «не был».
- Рекомендации основаны на объяснимых правилах и действующих предложениях. Priority не является ML-вероятностью.
- Импорт и результаты строк хранятся в PostgreSQL; Valkey используется для транспорта очереди. Сохраняйте lease, восстановление после сбоя и защиту от двойной обработки.
- Выгрузка не отправляет сообщения. Сохраняйте предпросмотр, cooldown, идемпотентность и блокировки конкурентного экспорта.
- Desktop подключается к серверу. Пароли БД и инфраструктура не встраиваются в установщик. Сессия остаётся в native HTTP-клиенте; не отключайте проверку origin и не разрешайте произвольные URL/файловые пути из webview.

## Проверки

- Frontend: `cd apps/web`, `npm ci`, `npm run build`.
- Backend: Python >=3.13, `python -m pip install -e 'apps/api[test]'`, `python -m pytest -q apps/api/tests`. Тестовая БД обязательно оканчивается `_test`.
- E2E: только отдельный Compose-проект `hryukers-e2e`, инструкции в README. Не очищайте рабочую демонстрационную базу.
- Desktop: инструкции в `docs/DESKTOP.md`. Не называйте Windows-сборку проверенной без успешного job на Windows.
- Изменения общей модели оформляйте миграцией Alembic. При изменении API синхронно обновляйте `docs/api/openapi.json` и `apps/web/src/api.generated.ts` через `npm run generate:api`.

В описании результата указывайте изменённое поведение, выполненные проверки и оставшиеся ограничения. Не подменяйте реальную интеграцию данными в интерфейсе.
