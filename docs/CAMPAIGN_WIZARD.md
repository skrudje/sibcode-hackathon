# Мастер создания кампании

Единый экран `/campaigns/new` объединяет три шага: аудиторию, предложение и проверку контактов. Он доступен из кампаний, карточки рекомендации и радара. Отдельные разделы сохраняются для управления готовыми объектами.

Аудитория выбирается из сегментов, задаётся через существующий конструктор условий либо берётся из радара. Изменение готовых условий создаёт новую аудиторию и не переписывает общий сегмент. Для назначения показываются только совместимые активные арендаторы. Можно использовать действующее предложение из существующего правила или подготовить новое; отдельного каталога предложений пока нет. Текст нового предложения хранится в черновике отдельно для каждого назначения.

На последнем шаге маркетолог задаёт название и канал Email/SMS. До сохранения сервер показывает количество кандидатов, доступных контактов, причины исключений и пример получателей. Проверка использует те же правила, что CSV: полноту истории, контакты, конфликты, дубли и семидневное ограничение частоты. Предпросмотр не сохраняет объекты и не резервирует контакты. Переход назад сохраняет поля формы; выход из мастера отбрасывает черновик.

`POST /api/v1/campaigns/audience-preview` проверяет источник аудитории. `POST /api/v1/campaigns/preview` проверяет полный черновик и возвращает токен состояния аудитории, предложения и контактов. `POST /api/v1/campaigns/prepare` повторяет проверку, сравнивает токен и сохраняет необходимые записи одной транзакцией. При изменении данных возвращается 409 и требуется обновить предпросмотр. При отсутствии доступных контактов создание недоступно. Повтор одного действия защищён ключом идемпотентности, включая конкурентные запросы.

Готовый сегмент используется повторно. Правило используется повторно, если выбранное предложение уже связано с этим сегментом; иначе создаётся правило для новой аудитории с копией предложения. Создание кампании не формирует CSV и не отправляет сообщения: выгрузка остаётся отдельным действием на странице кампании с повторной проверкой и блокировками контактов.

Старые API создания кампаний и `/radar/campaigns` сохранены для совместимости. Схема БД не изменяется. Контракт обновляется в OpenAPI и сгенерированных TypeScript-типах.
