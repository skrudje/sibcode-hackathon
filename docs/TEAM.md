# Совместная разработка втроём

Репозиторий: https://github.com/skrudje/sibcode-hackathon. Общая ветка — `main`. Ветка задачи — `feat/<имя>-<задача>` или `fix/<имя>-<задача>`. Каждый разработчик запускает Codex в корне своего клона, чтобы агент прочитал `AGENTS.md`.

## Скачать и начать

```bash
git clone https://github.com/skrudje/sibcode-hackathon.git
cd sibcode-hackathon
git switch -c feat/<имя>-<задача>
```

Скопируйте `.env.example` в `.env` (`cp` на Linux, `Copy-Item` в PowerShell) и запустите `docker compose up --build -d --wait`. Данные каждого локального запуска независимы. Desktop-разработка описана в [DESKTOP.md](DESKTOP.md).

Перед новой задачей обновляйте локальный `main`:

```bash
git switch main
git pull --ff-only
git switch -c feat/<имя>-<задача>
```

Сохранив изменения и выполнив нужные проверки:

```bash
git add <файлы-задачи>
git commit -m "feat: конкретное изменение"
git push -u origin HEAD
```

Откройте pull request в `main`. Один из коллег проверяет изменение. Перед слиянием дождитесь проверок CI. Для обновления feature-ветки используйте `git fetch origin` и `git merge origin/main`: это не требует переписывать опубликованную историю.

## Первое разделение задач

| Направление | Основные файлы | Следующая полезная задача |
|---|---|---|
| Desktop и интерфейс | `apps/web/src-tauri`, `apps/web/src`, `docs/DESKTOP.md` | Удобство настройки сервера, native UX, проверка установщиков на реальных ноутбуках |
| Данные и интеграции | `apps/api/app/modules/ingestion`, `modules/customers`, адаптеры | Уточнить реальные форматы, добавить настройки источников и управление coverage |
| Продуктовая логика и качество | `modules/segments`, `modules/exports`, тесты | Расширить бизнес-правила, проверить пограничные сценарии и подготовить показ жюри |

Это зоны координации, а не запрет менять чужие файлы. Изменения `models`, `main.py`, OpenAPI, миграций, lock-файлов и CI заранее обозначайте в задаче, чтобы двое агентов не меняли один контракт независимо.

## Что передать своей нейронке

```text
Прочитай AGENTS.md и README.md в корне, затем docs/TEAM.md и docs/DESKTOP.md.
Работай в текущей feature-ветке, сохраняй чужие изменения.
Моя задача: <одно конкретное изменение и ожидаемое поведение>.
Перед реализацией найди затрагиваемые API и инварианты.
Реализуй задачу, выполни подходящие проверки и перечисли изменённые файлы.
Не меняй общий контракт, миграции или зависимости без необходимости задачи.
```

Владелец репозитория выдаёт коллегам доступ Write через GitHub Settings → Collaborators. Публичный репозиторий можно клонировать без приглашения; отправка веток в него требует доступа.
