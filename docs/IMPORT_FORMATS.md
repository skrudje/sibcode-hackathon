# Свои CSV/XLSX и полнота истории

Файл загружается в существующий источник соответствующего типа: `crm_csv` принимает CSV, `pos_xlsx` — XLSX. Один источник относится к одному арендатору. REST JSON использует отдельный адаптер.

## Форматы файлов

- CSV: UTF-8, BOM допустим, разделитель — **запятая**, первая строка содержит заголовки. Значения с запятыми заключайте в двойные кавычки.
- XLSX: таблица на **активном листе**, первая строка содержит заголовки. ID, телефоны и даты сохраняйте текстом, чтобы сохранить начальные нули и часовой пояс.
- Пробелы вокруг названий колонок удаляются. Регистр названий значим. Пустые и повторяющиеся заголовки отклоняются; проверяются также дубли необязательных колонок. Дополнительные именованные колонки допускаются и не используются адаптером.
- Лимиты: 10 MiB на файл и 10 000 строк событий. Заголовок без строк событий считается пустым импортом.

| Содержание | Колонка CSV | Колонка XLSX | Требование |
|---|---|---|---|
| ID клиента в источнике | `customer_id` | `id_клиента` | Обязательно, непустая строка |
| ID события в источнике | `event_id` | `id_чека` | Обязательно, непустая строка |
| Тип события | `event_type` | `тип_события` | Обязательно: `visit`, `purchase`, `booking` |
| Время события | `event_time` | `дата_операции` | Обязательно, ISO 8601 с часовым поясом |
| Общий ключ клиента | `global_customer_key` | `единый_ключ` | Необязательно; связывает профили разных арендаторов |
| Имя | `full_name` | `имя` | Необязательно |
| Email | `email` | `email` | Необязательно |
| Телефон | `phone` | `телефон` | Необязательно, текст |
| Сумма | `amount` | `сумма` | Для `purchase` обязательна, неотрицательная, до 2 знаков после точки |
| Валюта | `currency` | `валюта` | `RUB`, обязательна при наличии суммы |

Время указывается, например, как `2026-10-30T16:00:00+07:00` или `2026-10-30T09:00:00Z`. Обычная Excel-дата без часового пояса не подходит. Допускается отклонение времени события вперёд до 5 минут относительно сервера. У `visit` сумма и валюта должны быть пустыми; у `booking` они необязательны и заполняются вместе.

Пример CSV:

```csv
customer_id,event_id,event_type,event_time,global_customer_key,full_name,email,phone,amount,currency
0007,receipt-0001,purchase,2026-10-30T16:00:00+07:00,MY001,Посетитель,visitor@example.invalid,,120.50,RUB
```

Готовый пример XLSX находится в `demo/templates/pos_B.xlsx`. Его демонстрационные даты зафиксированы; актуальные демофайлы интерфейс получает через защищённый `/api/v1/demo/files/{name}`.

Пустой общий ключ оставляет профиль в рамках конкретного источника. Совпадение email или телефона не объединяет разных людей. Повтор одного `event_id` в том же источнике с теми же данными считается дублем; изменённые данные существующего события считаются конфликтом.

## Где смотреть ошибки

Загрузка возвращает `202` и ID фонового задания. Состояние: `GET /api/v1/imports/{id}`.

При неверных заголовках задание получает `status=failed`, `failure_code=invalid_file_schema`. В `failure_message` перечисляются отсутствующие и повторяющиеся колонки, например:

```text
Отсутствуют обязательные колонки: event_type, event_time. Повторяются колонки: customer_id.
```

Такой файл не обрабатывается построчно и автоматически не повторяется. Исправьте его и загрузите заново. Некорректные значения отдельных строк видны в `GET /api/v1/imports/{id}/errors`.

## Явное покрытие истории

Покрытие — утверждение оператора, что источник содержит **все события указанных типов за указанный период**. Успешная загрузка файла подтверждает обработку его строк. Полнота истории задаётся отдельно на основании сведений владельца источника.

API: `PATCH /api/v1/sources/{source_id}/coverage`. Нужны сессия текущего ТЦ и разрешённый `Origin`, как для остальных записывающих API. Успешный ответ `200` содержит обновлённый `Source`.

```json
{
  "coverage_from": "2026-07-01T00:00:00+07:00",
  "coverage_to": "2026-10-30T23:59:59+07:00",
  "covered_event_types": ["purchase"]
}
```

- Передайте хотя бы одно поле. Неуказанные поля сохраняются.
- Проверяется итоговая пара дат с учётом сохранённых значений: начало строго раньше окончания, окончание не позже текущего времени сервера. Обе даты содержат часовой пояс, сервер хранит UTC.
- Чтобы отметить неизвестный период, передайте обе даты как `null`. Только одна неизвестная граница не допускается.
- `covered_event_types` содержит уникальные `visit`, `purchase`, `booking`. Массив `[]` означает отсутствие заявленной полноты по типам событий. `null` для массива запрещён.
- Некорректный запрос возвращает `422`, изменения не сохраняются. Чужой или отсутствующий источник возвращает `404`.
- Импорт не выводит покрытие из дат покупок и не расширяет его автоматически. Новые события и `last_success_at` сохраняются независимо от заявленного периода.

Каждый запрос расчёта сегмента использует текущее покрытие. Если для окна сегмента или нужного типа события данных недостаточно, результат — `unknown`. Дата общего среза берётся из минимальной даты окончания покрытия участвующих источников, если все они известны; иначе используется текущее время. Конкретное значение возвращается в `evaluation.as_of`.

Для проверки с демоданными: сузьте начало покрытия книжного C до последних 30 дней при 90-дневном окне сегмента. Подходящих клиентов станет 0, `unknown` — 10, рекомендация G001 исчезнет с причиной `insufficient_history`. Верните исходный период — расчёт восстановится без повторного импорта.
