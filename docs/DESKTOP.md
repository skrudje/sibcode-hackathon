# Desktop для Linux и Windows

## Архитектура

Tauri 2 упаковывает React-интерфейс в нативное приложение. Сборка содержит локальные HTML/CSS/JS и Rust-слой подключения, а не открывает удалённый сайт. Клиент подключается к общей серверной платформе: FastAPI → PostgreSQL, worker/dispatcher → Valkey. Пользователю установленного клиента не нужны Python, Node.js и Rust.

Для локальной разработки сервер запускается через Docker Compose. Для совместной работы сотрудников нужен один доступный сервер с HTTPS и индивидуальными учётными записями. Установщик не содержит PostgreSQL, Docker или реальные пароли. Полностью автономный режим и синхронизация нескольких локальных баз в текущую архитектуру не входят.

Запросы desktop выполняет native HTTP-клиент Rust с cookie-сессией в памяти. Webview получает только относительные API-запросы; произвольные внешние адреса и редиректы запрещены. При смене адреса сервера сессия сбрасывается. Адрес сервера сохраняется отдельно от пароля. HTTP разрешён только для loopback-разработки; удалённый сервер требует HTTPS.

В браузере остаются same-origin запросы через Nginx. В desktop нет необходимости ослаблять CORS или CSRF backend: native-слой передаёт origin выбранного сервера, который должен присутствовать в его `ALLOWED_ORIGINS`.

## Зависимости разработчика

Для всех ОС: Git, Node.js 24 LTS, Rust stable через rustup. Зависимости JS устанавливаются в `apps/web` командой `npm ci`; Rust-зависимости фиксируются в Cargo.lock. Актуальные требования Tauri: https://v2.tauri.app/start/prerequisites/.

Linux (Debian/Ubuntu/Kali):

```bash
sudo apt-get update
sudo apt-get install build-essential curl pkg-config libwebkit2gtk-4.1-dev libssl-dev librsvg2-dev libayatana-appindicator3-dev patchelf
```

Windows: Microsoft C++ Build Tools с компонентом Desktop development with C++, WebView2 Runtime, Rust target `x86_64-pc-windows-msvc`. Используйте PowerShell; сервер запускается в Docker Desktop с Linux containers/WSL2.

## Запуск из исходников

Из корня репозитория подготовьте `.env` по `.env.example`, затем:

```bash
docker compose up --build -d --wait
cd apps/web
npm ci
npm run desktop:dev
```

Сервер по умолчанию — `http://127.0.0.1:5180`. Dev-окно интерфейса использует отдельный порт 1420, поэтому не конфликтует с Nginx. В настройках подключения можно указать другой сервер. Учётная запись для локальной демонстрации описана в README.

## Сборка установщика

Из `apps/web`:

```bash
npm run desktop:build
```

Linux собирается на Linux, Windows — на Windows. Результаты находятся в `apps/web/src-tauri/target/release/bundle/`. Windows: NSIS `.exe`. Linux: `.deb` и AppImage. Нельзя считать Windows-сборку проверенной по одному успешному Linux-билду.

Workflow `.github/workflows/desktop.yml` собирает обе платформы и сохраняет установщики как Actions artifacts. Он не публикует GitHub Release автоматически. Проверка подписи Windows и автообновления требуют отдельной настройки для выпуска; прототип не содержит сертификатов.

Первая проверенная сборка обеих платформ: [GitHub Actions, 31 октября 2026](https://github.com/skrudje/sibcode-hackathon/actions/runs/41177948644). Скачайте `hryukers-Linux-x64` или `hryukers-Windows-x64` в разделе Artifacts этого запуска. Для скачивания артефактов GitHub требует вход. Срок хранения — 14 дней; затем соберите приложение из исходников или запустите workflow заново. Артефакты привязаны к конкретному коммиту, поэтому для дальнейшей разработки ориентируйтесь на актуальный `main`.

Linux-окно дополнительно запускалось в изолированном Xvfb-окружении. Windows-установщик собран на Windows runner; ручной показ и работа с системным файловым диалогом на реальном Windows-ноутбуке пока не проверялись.

## Проверка Linux без установки Rust/GTK на хост

Для окружения с Docker есть `infra/desktop.Dockerfile`. Пример Linux-сборки из корня:

```bash
docker build -t hryukers-desktop-builder:local -f infra/desktop.Dockerfile .
docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp -e CARGO_HOME=/workspace/.data/cargo -e CARGO_BUILD_JOBS=2 -v "$PWD:/workspace" hryukers-desktop-builder:local npm run desktop:build -- --bundles deb
```

Перед запуском в `apps/web` выполните `npm ci`. Не переносите node_modules с Windows в Linux-сборщик; устанавливайте зависимости внутри соответствующей ОС. Этот контейнер предназначен для сборки, а не для установки приложения конечному пользователю.

## Native UX

Рабочее окно NEXA имеет закреплённое верхнее меню, панель инструментов и строку состояния. Внешний стиль — синий фон с сеткой, тёмные контуры и лаймовый акцент. Имя продукта в заголовке окна и установщика — NEXA; идентификатор приложения `ru.hryukers.cdp` сохранён, поэтому настройки сервера остаются доступны. Прокручивается содержимое раздела; в каталоге клиентов таблица прокручивается отдельно от поиска и пагинации. Системная рамка и управление окном остаются нативными средствами ОС.

- `Ctrl+K` — найти и открыть раздел; стрелки выбирают результат, `Enter` открывает, `Esc` закрывает. На macOS также поддерживается `Cmd+K`.
- `Ctrl+B` — свернуть или развернуть меню. Предпочтение сохраняется на компьютере. При вводе в поле сочетание не перехватывается.
- `Alt+1`…`Alt+8` — перейти к разделу по его порядку в меню; `Alt+7` открывает радар, `Alt+8` — интеграции.
- Кнопка «Обновить» запрашивает актуальные данные. Состояние доступности сервера проверяется каждые 30 секунд.

При запуске клиент автоматически использует сохранённый сервер, а при первом запуске — локальный адрес по умолчанию. Диалог подключения сам не открывается. «Настройки» находятся на верхней панели инструментов и под формой входа; поле адреса появляется только после «Изменить сервер». Сохранение неизменённого адреса не сбрасывает сессию. При недоступности сервера на запуске вместо формы входа показывается экран с повторной попыткой и доступом к настройкам. Команда выхода сохраняет локальную оболочку и возвращает к форме входа без перехода на внешний URL.

Покупки и профили остаются на сервере. CSV выгружается через диалог «Сохранить как» с authenticated-запросом; пароль и cookie не попадают в URL скачивания. При недоступном backend приложение показывает ошибку подключения и даёт изменить адрес. Для проверки browser-режима сохраняются существующие E2E.

## Подключение и повторная попытка

В desktop состояние сервера видно в закреплённой строке состояния рабочего пространства и в «Настройках». Адрес показывается в форме «Изменить сервер». Проверка использует native-команду readiness для `/api/v1/health/ready`, включая готовность PostgreSQL и очереди, с таймаутом 8 секунд. Она повторяется каждые 30 секунд и после ошибки IPC-запроса. В настройках есть «Проверить подключение», а на экране недоступности — «Повторить». После восстановления связи ошибочные запросы страниц запрашиваются заново. Ошибка начальной загрузки сессии не маскируется формой входа; форма появляется при ответе API 401.

В настройках «Сохранить и подключиться» сначала проверяет новый адрес. На время проверки страницы скрыты, взаимодействие с ними заблокировано, запросы отменяются. Ошибка оставляет предыдущий адрес и его native-сессию. Повторное подключение к тому же нормализованному адресу проверяет доступность и сохраняет вход. Успешная смена адреса создаёт новый HTTP-клиент без cookie, очищает кэш и локальное состояние страниц, переводит навигацию на обзор и требует нового входа. Каждый IPC-запрос привязан к номеру подключения; старые команды и ответы после переключения отклоняются. Настройки содержат только адрес и номер подключения, без cookie и пароля. После перезапуска приложения вход выполняется заново.

Выбор CSV/XLSX использует файловый input WebView (нативный выбор файла; `dragDropEnabled: false` сохраняется для Windows). Лимит файла — 10 MiB; сервер повторно проверяет формат и размер. Выгрузка скачивается через авторизованный native-запрос и сохраняется через системный диалог. Отмена показывает «Сохранение отменено» и позволяет повторить скачивание той же выгрузки. Отмена сохранения не отменяет уже созданную серверную выгрузку и не снимает cooldown; для повторного скачивания не нужно снова формировать CSV.

## Автоматические проверки перед установкой

Из `apps/web` после `npm ci`:

```bash
npm run generate:api
npm run build
npm run test:desktop:ui
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

`test:desktop:ui` поднимает Vite на свободном порту 5182 и проверяет недоступность, повторную попытку и ошибку смены адреса через изолированный IPC-адаптер. Backend ему не требуется. Перед первым запуском установите Chromium: `npx playwright install chromium`. Для уже установленного браузера можно передать `E2E_BROWSER_PATH=/usr/bin/chromium`. Это проверка React/IPC-контракта, она не проверяет установленное приложение.

Отдельный сценарий с **реальным API** использует только чистое окружение `hryukers-e2e` из README. Не запускайте его на рабочей демонстрационной базе. Он импортирует CSV/XLSX с едиными колонками phone/email/time через файловый input, открывает созданный профиль, создаёт кампанию из радара и CSV, проверяет отмену/повторное скачивание и вход после смены origin. IPC-адаптер теста хранит отдельные cookie jars, а результат файлового диалога моделируется; native-диалог проверяется вручную ниже.

```bash
# Из корня: подготовить .env и .env.e2e по README, сохраняя существующие настройки.
docker compose -p hryukers-e2e --env-file .env.e2e up --build -d --wait
cd apps/web
npm run test:desktop
```

Сценарий ожидает заполненный пример (`SEED_WORKSPACE_DATA=true`) с завершёнными начальными загрузками. Перед первым прогоном дождитесь обработки всех девяти источников. Для повторения следуйте reset **только тестовых** volumes в README. Оба набора тестов меняют только тестовые данные; полный browser E2E можно выполнить первым, а desktop-сценарий — после него на том же подготовленном тестовом сервере. При `E2E_BASE_URL` должны работать оба origin (`localhost` и `127.0.0.1`) на одном порту и оба должны быть в `ALLOWED_ORIGINS`.

## Приёмка установленного приложения на Linux

Результаты проверок: [VERIFICATION.md](VERIFICATION.md). На машине проверки сначала запишите ОС, версию WebKitGTK, тип сессии X11/Wayland, коммит, имя установщика и SHA-256. Сборка и запуск из исходников не заменяют установку пакета.

1. На подготовленной машине соберите `npm run desktop:build -- --bundles deb,appimage` или возьмите артефакт **этого коммита** из Desktop installers. Установите `.deb` через `sudo apt install ./<имя>.deb`, найдите приложение в меню и запустите. Отдельно проверьте AppImage: разрешение на исполнение, запуск, зависимость от FUSE. Не отключайте sandbox WebKit ради успешного результата.
2. Поднимите отдельный `hryukers-e2e` по README. В настройках клиента укажите `http://127.0.0.1:5181`. При остановленном сервере дождитесь ошибки, проверьте адрес и кнопку повторной попытки. После запуска сервера нажмите её; статус должен стать «Сервер доступен», затем должна появиться форма входа. Снимите `01-offline.png` и `02-login.png`.
3. Войдите демоучётной записью, проверьте обзор и остальные разделы верхнего меню. В интеграциях запустите «Обновить» у арендатора. В источниках выберите CSV и XLSX с колонками phone/email/time (формат — в IMPORT_FORMATS.md, тестовый Excel — `apps/web/tests/fixtures/contacts.xlsx`). Проверьте журнал, ошибки строк и профиль по телефону или email. Отмените выбор файла и повторно выберите тот же файл: отмена не создаёт задания, повтор не дублирует события. Снимите `03-imports.png` и `04-profile.png`.
4. В кампании сформируйте CSV, нажмите «Скачать CSV». В **системном** диалоге нажмите «Отмена»: сообщение об отмене, файл не создан, число выгрузок в журнале не изменилось. Снова скачайте **ту же** выгрузку и сохраните в папку с пробелами и кириллицей. Проверьте UTF-8, заголовки, контакты выбранной аудитории, отсутствие исключённых контактов, сообщение «CSV сохранён». Снимите диалог `05-save-dialog.png` и результат отмены `06-save-cancel.png`. Проверьте повторное скачивание и ошибку записи в недоступную папку.
5. Откройте профиль. Попробуйте недоступный новый адрес — предыдущая сессия должна сохраниться. Затем смените адрес на `http://localhost:5181`: старые страницы исчезают, навигация переходит на `#/`, требуется новый вход. Вернитесь к первому адресу — требуется новый вход и там. Попробуйте переключение во время загрузки; старые ответы не должны восстановить профиль. Повторное подключение к тому же адресу не разлогинивает. Снимите `07-server-changed.png`.
6. Закройте приложение полностью и запустите через меню: адрес сохранён, сессия требует входа. Проверьте выход, повторный вход, масштаб экрана ноутбука 100%/125%/150%, окно 900×640 и системные диалоги на используемой X11/Wayland-сессии. Повторите краткий прогон через AppImage. Удаление пакета не должно затронуть данные сервера.

Для каждого шага запишите PASS/FAIL/BLOCKED, ожидаемый и фактический результат, ОС и имя скриншота. Не включайте реальные контакты и секреты в отчёт. Подписи установщиков, автообновление, удалённый HTTPS с сертификатом команды и сетевые прокси требуют отдельной проверки окружения.

## Настройки источников и полнота истории

Контракт интегрирован: администратор изменяет явный период через `PATCH /sources/{id}/coverage` или сохраняет его вместе с API и расписанием через `PATCH /integrations/{id}`. Интерфейс находится в «Интеграциях». Новые источники принимают только взаимодействия; гарантируемый тип — `interaction`. Старые типы доступны в API для исторических источников.

Период не вычисляется по событиям файла. После сохранения интерфейс перечитывает источник и зависимые сегменты, рекомендации и предпросмотры кампаний. Backend проверяет границы дат, часовые пояса, типы событий, роль администратора и принадлежность ТЦ. Подробности — [INTEGRATIONS.md](INTEGRATIONS.md) и [IMPORT_FORMATS.md](IMPORT_FORMATS.md).
