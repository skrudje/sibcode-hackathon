# Проверка MVP 0.1.0

Команда «Хрюкерсы», кейс №2. Проверено локально 31 октября 2026 года.

## Переход на сопоставление по контактам

Актуальная логика описана в [IDENTITY.md](IDENTITY.md). Источникам больше не нужен общий ключ клиента.

- Backend: 43 теста прошли на Python 3.13.18 и отдельной PostgreSQL 16.15. Проверены совпадения по телефону/email без общего ключа, нормализация, конфликты без побочных записей, изоляция ТЦ, конкурентные импорты, перенос локальной истории, миграция сохранённых контактов и идемпотентность старых событий.
- Alembic `check`: модели соответствуют миграциям, новых операций не обнаружено.
- Генерация TypeScript из OpenAPI и production-сборка интерфейса прошли на Node.js 24.
- Обновлённый browser E2E загружается Playwright (4 сценария), но не запускался: в текущем окружении нет доступа к Docker socket для отдельного Compose-проекта. Результаты прежнего E2E ниже относятся к исходной версии.
- Активное демо: 10 профилей, 18 событий, сегмент 5/3/2; email-предпросмотр — 2 адресата из 5. Проверяется backend-тестами полного сценария.

## Desktop и перенос в `/data/sibcode`

После переноса проверены вход через HTTP, сохранность 10 профилей/18 событий, backend-тесты и запуск Compose из нового корня. Контейнеры пересозданы с новой рабочей папкой; named volumes сохранены. Локальный venv обновлён для нового пути, в Git он не включён.

- Native Rust: 3 теста прошли — допустимые адреса сервера, невозможность выйти за пределы API, cookie-сессия и точная передача multipart-данных.
- Дополнительный Playwright-сценарий проверяет frontend/IPC-контракт, hash-навигацию, настройки сервера и отображение ошибки подключения. В нём IPC имитируется, а native HTTP проверяется отдельно Rust-тестами.
- Linux native binary собран через Tauri CLI. В Xvfb процесс работал 12 секунд без аварийного завершения; затем тест штатно остановил его по timeout. Это проверка старта, а не полный native UI E2E.
- [Desktop CI](https://github.com/skrudje/sibcode-hackathon/actions/runs/41177948644): Linux `.deb`/AppImage и Windows NSIS `.exe` собраны на соответствующих ОС. Rust-тесты прошли на обоих runner.
- [Product CI](https://github.com/skrudje/sibcode-hackathon/actions/runs/41178004966): backend и frontend прошли проверки, сгенерированные TypeScript-типы соответствуют OpenAPI.

Установщики не подписаны; ручная проверка установленного Windows-приложения и диалога сохранения на реальном ноутбуке остаётся задачей команды.

Backend-проверки покрывают идентификацию без ошибочного слияния по общему контакту, изоляцию ТЦ, серверную авторизацию, три адаптера данных, дубли и конфликты событий, восстановление задания после сбоя, достаточность истории, объяснения рекомендаций, формат ответов API и конкурентное создание выгрузок.

Браузерные сценарии проверяют вход, полный путь от импорта до CSV и изменения рекомендации после новой покупки, создание сегмента/правила/кампании и отсутствие горизонтального переполнения страницы на ширине 390 px. Проверка CSV подтверждает содержимое скачанного файла. В полном пользовательском сценарии ошибок JavaScript не обнаружено.

Для тестов использовались отдельная БД с суффиксом `_test` и отдельный Compose-проект `hryukers-e2e`. Основная демонстрация не использовалась для разрушительных тестов. Инструкции воспроизведения — в [README](../README.md).

## Состояние основной демонстрации

Данные загружены через те же API импорта, которые вызывает интерфейс: REST JSON → POS XLSX → CRM CSV. Результат: 22 строки, 18 принятых событий, один дубль и три отклонённые строки. Сегмент: 5 подходящих, 3 неподходящих, 2 с недостаточными данными. Выгрузка и дополнительная покупка в C оставлены для показа команды.

## Границы проверки

Это локальный MVP с синтетическими данными и демонстрационным REST-источником. Подключение CRM заказчика, реальная отправка сообщений и промышленная нагрузка не проверялись. Рекомендации основаны на редактируемых бизнес-правилах. Периоды полноты источников заданы явно; их согласование и обновление для реальных интеграций остаются следующим этапом.

В pytest есть предупреждение о будущем изменении HTTP-клиента в Starlette TestClient; все тесты завершились успешно.
