# Кабинет представителя бренда

Представитель входит по email и паролю в то же приложение и получает отдельный интерфейс передачи данных. Аккаунт принадлежит одному магазину внутри одного ТЦ. Общая база клиентов и контакты других магазинов доступны только сотрудникам УК.

## Создание доступа

1. Администратор открывает «Интеграции → Сотрудники».
2. Указывает email, первый пароль от 12 символов и роль «Представитель бренда».
3. Выбирает магазин. Он должен быть активным, принадлежать этому ТЦ и использовать источник `contacts`.
4. Передаёт сотруднику бренда его учётные данные. После входа открывается кабинет его магазина.

Администратор может изменить назначение, роль или отключить доступ. Собственный доступ через этот интерфейс не изменяется. Существующие аккаунты marketer/admin сохраняют свои права; миграция добавляет nullable `users.tenant_id` и ограничение соответствия роли назначению.

## Передача таблицы

1. Выбрать CSV или XLSX до 10 MiB, максимум 10 000 строк и 200 колонок. Первая строка — заголовки. В Excel читается активный лист.
2. Сопоставить колонки со стандартными полями «Телефон», «Email» и «Время взаимодействия». Названия в исходной таблице могут быть произвольными. Повторяющиеся названия различаются по номеру колонки.
3. Время обязательно; для контакта достаточно телефона или email. Один столбец нельзя назначить нескольким полям.
4. Нажать «Проверить выбранные данные». Видны первые 10 преобразованных записей и число строк с корректным форматом/ошибками. Это проверка формата, а не проверка личности или окончательное разрешение конфликтов профилей.
5. Нажать «Передать … записей». В журнале своего магазина видны статус, принятые записи, дубли и отклонения с причинами.

CSV поддерживает UTF-8/BOM и Windows-1251, разделители запятую, точку с запятой и табуляцию. Даты: ISO 8601, `ДД.ММ.ГГГГ ЧЧ:ММ[:СС]`, дата без времени и значения datetime Excel. Для дат без часового пояса явно используется пояс ТЦ, показанный перед подтверждением. Дата без времени интерпретируется как 00:00 в этом поясе.

Пример исходной таблицы с произвольными колонками: [brand-upload.csv](../apps/api/fixtures/brand-upload.csv). Файл находится вместе с остальными тестовыми примерами, без отдельного каталога в корне репозитория.

Файл передаётся серверу для предпросмотра и разбирается в памяти. В хранилище импорта сохраняется только преобразованный CSV с phone/email/time; исходная таблица и лишние колонки туда не записываются. Предпросмотр не сохраняет события и не создаёт задание. При подтверждении корректные и некорректные строки проходят обычный worker: ошибки не теряются. Номера в отчёте — номера непустых записей без заголовка.

Сопоставление профилей, идемпотентность событий, конфликты и восстановление импорта выполняются существующим обработчиком. Новые записи создают `interaction`. Ручная таблица не меняет API cursor и не объявляет полноту истории. Прежние данные и автоматический опрос API продолжают работать.

## Границы доступа

- `/auth/me` и выход доступны всем вошедшим пользователям.
- `/brand/*` доступны только brand; магазин и источник берутся из серверной привязки, а не из параметров браузера.
- Представитель видит все загрузки источника своего магазина, включая API, и только их ошибки.
- Общие клиенты, контакты, сегменты, рекомендации, радар и выгрузки доступны только marketer/admin.
- Подключения, полнота истории и сотрудники остаются под управлением admin.
- Смена роли и отключение учитываются следующим запросом. Чужие загрузки в кабинете возвращают 404.

## API

- `GET /api/v1/brand/context` — магазин, источник и часовой пояс.
- `POST /api/v1/brand/imports/preview` — multipart file; необязательная строка mapping с JSON `{ "phone": 0, "email": 2, "time": 4 }`. Индексы с нуля; phone/email могут быть null, но не одновременно. Без mapping возвращается структура, с mapping — проверка выбранных полей.
- `POST /api/v1/brand/imports` — file и mapping; создаёт обычный ImportJob (202).
- `GET /api/v1/brand/imports` — журнал своего источника, limit/offset.
- `GET /api/v1/brand/imports/{job_id}/errors` — ошибки только своей загрузки, limit/offset.

Доступы создаются существующими `POST /team` и `PATCH /team/{id}` с role=brand и tenant_id. Для marketer/admin tenant_id должен быть null. Доступ к сырым персональным контактам общей базы роль brand не получает.
